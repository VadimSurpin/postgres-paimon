# v2.0.0

PostgreSQL to Apache Paimon replication on **logical replication slots**: a pure-SQL `paimon_slot`
extension plus an external Java writer (`paimon-writer.jar`). This replaces the C++ table access
method (`paimon_heap`) of v1.x, which now lives on the `pg-extension` branch and is no longer
developed here. **v2.0.0 is not an upgrade of v1.x**: the storage model, the setup and the Paimon
layout are different. Re-bootstrap into a new warehouse; see the guide.

## Highlights

* **Effectively-once delivery.** The slot advances only after a Paimon commit; a replayed
  transaction is filtered by its commit identifier. Verified with `kill -9` at every step.
* **Faithful changelog.** `REPLICA IDENTITY FULL` and `changelog-producer = input`: a real `-U`/`+U`
  pair for every update, including rows whose TOASTed columns were not touched.
* **History tables.** Every table `T` gets an append-only `T_hist`, partitioned by day, with one row
  per row image (`+I`, `-U`, `+U`, `-D`), never collapsed; archived as `T_hist_<lsn>` on every DDL.
* **Tables without a primary key** are replicated as append-only operation logs.
* **DDL follows the data**, with guardrails that refuse what the writer could not apply faithfully.
* **No poison records.** Value guards, type-change rules and `paimon.health()` refuse or report
  what would stop the writer; there is no dead-letter table. `PGPAIMON_SKIP_LSN` is a break-glass.
* **Operational safety.** The warehouse remembers its cluster (system identifier) and the writer
  refuses a different one; the slot is created for failover; an invalidated slot stops the writer
  with its cause (`paimon.slot_health()`, `scripts/rebootstrap.sh`); `PGPAIMON_TXN_MAX_BYTES`
  bounds a transaction's memory; every session setting that changes a value's text is pinned.
* **Verified against TPC-C** on GitHub Actions: every row, the changelog and every history table
  of PostgreSQL 18 compared with Paimon (`tpcc.yml`, manual dispatch).
* **Rules for developers and administrators** (guide, section 8): every action to avoid, marked
  REJECTED, STOPS WRITER, REINIT / HISTORY LOSS or NOT DETECTED.

## Requirements

PostgreSQL 18 with `wal_level = logical`; JDK 17 (the writer jar bundles Paimon 1.4.1).

## Known limits

* S3 support is wired in but not exercised here (no MinIO in the test environment).
* Not detected, and documented as such: a slot consumed by another client after a writer crash, a
  file-level restore that kept the slot, a changed `PGPAIMON_COMMIT_USER`, an unregistered new
  partition. A real failover, `pg_upgrade` and point-in-time recovery are untested.
* Any role that can read `paimon.secret` (including `pg_read_all_data` members) can forge DDL
  messages: a known residual risk, see the guide, section 5.
* The extension's SQL script is still version 1.0 and has no upgrade path between commits.
